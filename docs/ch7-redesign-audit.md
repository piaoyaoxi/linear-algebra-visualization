# 第七章重做审查记录

> 内部制作资料，不进入学生页面。

## 一、上一版为什么失败

上一版在功能层面能够运行，但教学层面没有达到项目样板章的标准。根本问题不是缺少动画，而是页面没有回答学生进入实验时最先遇到的三个问题：

1. 我现在要观察什么？
2. 我应该先操作哪一个控件？
3. 操作以后，哪一个变化构成数学结论？

具体表现为：

- 九节交互使用近似相同的“控件 + 图表 + 数据卡”模板，概念之间缺少独立的视觉语言。
- `interactive.task` 与 `interactive.prompts` 虽然存在于内容数据中，却没有在实验界面中展示。
- 控件先于任务出现，学生容易把实验理解成无目标地试按钮。
- 同一屏幕同时出现过多小矩阵、数字和状态，视觉注意力没有主次。
- 默认状态往往只是一个数值样例，没有先制造需要解释的数学现象。
- 浏览器测试主要验证“能点击、无报错、无溢出”，没有验证任务是否可见、结论是否能被操作推出。

## 二、从第四章成熟页面提取的标准

第四章第一节及其他成熟小节的共同优点是：

- 一次只提出一个明确问题。
- 先给可见对象，再让对象变化，最后把图像落回公式。
- 页面有编号或阶段结构，学生知道当前位于哪一步。
- 颜色持续代表同一个数学对象，而不是用于装饰。
- 操作结果会形成一句完整结论，而不是只更新若干数值。
- 复杂概念被拆成多个小实验，而不是压进一个万能面板。

第七章重做采用同一标准，但不照搬第四章的网格变换外形。

## 三、全章统一重做规则

每个实验必须依次包含：

1. **实验问题**：一眼能读懂的主问题。
2. **操作任务**：明确告诉学生第一步做什么。
3. **阶段导航**：复杂实验拆成若干连续阶段。
4. **主工作区**：只突出当前阶段需要观察的对象。
5. **判定或结论**：把操作结果写成完整数学语句。
6. **继续探索**：只保留少量能够触及边界情形的提示。

此外：

- 任务文字必须位于控件之前，在桌面与手机端均保持可读字号。
- 任何坐标变换都必须区分“几何对象移动”和“同一对象的坐标记录改变”。
- Jordan 链必须区分完整算子 `T` 与幂零部分 `N=T-λI`，不能暗示 `T` 本身必然把向量送到零。
- 最小多项式实验必须检查整个空间，而不是只检查一个特征方向。
- 所有特殊状态均需单独解释：零子空间、整个空间、无实特征方向、不可对角化和零变换。

## 四、逐节重做方向

| 小节 | 上一版主要问题 | 重做后的核心任务 |
| --- | --- | --- |
| §1 定义 | 两个检验同时堆在一屏，学生不知道先看哪里 | 分成原点快检、加法两条路径、数乘两条路径；终点差异直接形成反例 |
| §2 运算 | `T+S`、`TS`、`ST` 混在同一面板 | 分开逐点相加、先后复合和倒序撤销，用机器管线显示输入—中间量—输出 |
| §3 矩阵 | 一开始就换基，跳过“列从哪里来” | 先逐列发送基向量，再用线性组合重建任意向量，最后才比较不同基下的记录 |
| §4 特征 | 扫描器只有误差数字，方向关系不够突出 | 在同一平面持续显示候选直线、`v` 与 `Av`，通过非零、共线、伸缩比三道判定门 |
| §5 对角化 | `P`、`D`、`P⁻¹` 只是拥挤的小矩阵 | 把坐标翻译、独立缩放、回到原坐标拆成三步；几何画布只显示真实空间中的 `x` 与 `Ax` |
| §6 核与值域 | 两边图形存在，但没有显示同一纤维为何得到同一输出 | 在输入端显示 `x+ker(T)`，输出端同步显示共同像，并用样本描出值域 |
| §7 不变子空间 | 用一个向量代表整个子空间，证据不足 | 直接比较整条 `W` 与整条 `T(W)`，再用适配基下的左下角系数核对是否泄漏 |
| §8 Jordan | 链条符号先行，且容易混淆 `T` 与 `N` | 从“特征向量不够”出发，用广义特征向量修复；明确只有幂零部分沿链归零 |
| §9 最小多项式 | 只看一个方向便容易误判为全局消去 | 对一组基的所有方向逐一施加候选多项式，区分局部消去、全局消去与最低次数 |

## 六、第二轮视觉审查：为什么“功能正确”仍然不像线性代数

用户实机截图暴露出上一轮自动验收没有覆盖的根本问题：页面虽然能够切换状态，却仍然以后台仪表盘的方式组织数学。四个等宽知识卡、多个指标块与小尺寸 SVG 同时争夺注意力，空间、方向、子空间和算子作用反而退到次要位置。

本轮据此确定以下视觉原则：

1. **几何对象是主角，控件和数字是旁白。** 每个实验先给一幅占据主要宽度的几何场景，再在旁边解释当前结论。
2. **一幅图只承担一个认知动作。** 输入关系、算子作用和输出关系按照阶段展开，不把所有状态压进同一张小图。
3. **颜色代表对象而非装饰。** 输入向量、第二个输入、输出、成功闭合与反例缺口在全章保持稳定语义。
4. **向量只画成有向线段。** 箭头末端不附加圆点；只有确实代表“空间中的点、样本或共同像”时才单独绘制圆点。
5. **坐标记录与几何移动必须分开。** 换基和对角化不得把 `P^{-1}x` 画成真实向量被搬到另一空间。
6. **公式必须由图像推出。** 公式出现在学生已经看到闭合、共线、压缩、保持或链传递之后，而不是先用大公式卡占据页面。

## 七、实机问题的代码根因

### 1. 箭头顶端圆点

旧 SVG 工具在每次绘制向量后统一追加端点 `<circle>`，所以所有向量都呈现成“线 + 三角箭头 + 圆球”的错误符号。新 renderer 将向量与点完全拆开：

- `arrowPath()` 把箭杆与箭头画成一条闭合路径，不依赖 marker，也没有端点圆；
- `point()` 仅在核的纤维样本、不变子空间样本和共同像等确有点语义的位置调用；
- 浏览器验收逐一检查向量必须是闭合路径，且不能退回 marker 箭头。

### 2. 滑杆只能点按、不能连续拖动

旧实现监听 range 的 `input` 后立即重建整个实验 DOM，正在被鼠标按住的 `<input>` 会在第一次事件后被删除。因此点击可以改变一次数值，持续拖动却会中断。重做后虽然保留了原生 range，实机检查仍发现某些浏览器只能点击轨道，不能稳定连续拖动，因此又补上了显式的鼠标和触摸拖动逻辑。

新实现把控件挂载与场景重绘分离：

- range 节点只创建一次；
- 鼠标和触摸位置显式映射到参数值，拖出滑轨后仍持续更新，释放时才结束；
- `input` 事件只更新状态、SVG 场景与结论，控件本身保持在 DOM 中；
- 特征方向还支持直接在主 SVG 上拖动。

### 3. 四列卡片导致公式断裂

旧版把正式概念强制压入四列，长公式在窄卡片内换行，中文标点与公式块互相挤压。新正式内容改为：

- 一个大幅核心问题与核心关系；
- 纵向编号概念序列；
- 最多两列的性质说明；
- 手机端全部单列。

## 八、九节的独立几何语言

| 小节 | 主视觉 | 学生通过图像得到的结论 |
| --- | --- | --- |
| §1 定义 | 输入、输出双平面与平行四边形 | 两条计算路径终点重合才保持加法或数乘 |
| §2 运算 | 图形与探针通过变换流水线 | 逐点相加没有先后，复合顺序通常改变结果 |
| §3 矩阵 | 基向量逐一进入算子并成为矩阵列 | 矩阵列来自基向量的像，任意输入由列重建 |
| §4 特征 | 方向罗盘、候选直线、`v` 与 `Av` | 特征方向是一整条保持自身的一维子空间 |
| §5 对角化 | 沿特征方向分解、独立缩放、重新合成 | 对角化把复杂作用拆成互不混合的一维缩放 |
| §6 核与值域 | 输入纤维、多个样本与输出共同像 | 核表示不可见差异，值域表示可达输出 |
| §7 不变子空间 | 同一平面中的整条 `W`、整条 `T(W)` 与夹角 | 不变性要求整个像子空间仍留在 `W` 内 |
| §8 Jordan | 特征直线、广义方向、缩放与剪切 | `N=T-λI` 记录链传递，完整 `T` 通常不归零 |
| §9 最小多项式 | 所有基方向的同步消去轨道 | `p(T)=0` 是全空间关系，且还要比较最低次数 |

本轮不为了“像 3Blue1Brown”而加入装饰性背景图。核心概念需要精确、连续、可操作的几何关系，因此采用高质量响应式 SVG；只有未来出现无法通过精确几何表达的章节封面或情境插图时，才引入生成图像。图像必须服务概念，不能替代数学关系。

## 九、2026-07-23 公开预览逐节复审

本轮在真实公开预览中逐节打开九个实验，并与 `main` 中第四章第一节、第五章第一节和第一章第一节并排复核。结论是上一轮虽然消除了部分低级错误，但仍然没有达到成熟章节的教学与视觉标准，不能继续在现有构图上做局部润色。

成熟页面提供的可复用标准不是某一种固定卡片，而是以下四点：

1. 主要数学对象占据最大面积，控件紧贴它，数据只作旁证；
2. 一次操作只改变一个清楚的数学关系；
3. 两个视图同时出现时，必须表达同一对象的准确对应；
4. 结论是学生刚刚看到的现象的语言化，不是额外的信息面板。

逐节确认的问题与新的唯一核心动作如下。

| 小节 | 公开预览中确认的问题 | 本轮唯一核心动作 | 新构图 |
| --- | --- | --- | --- |
| §1 | 拖动目标不可见，箭头标签拥挤，双平面仍像静态报告 | 拖动 `u`、`v` 的明确圆环手柄，让两条路径闭合或裂开 | 左侧输入平行四边形，右侧只保留两条输出路径与一个终点间隙 |
| §2 | 三个轮廓互相覆盖，学生不能分辨输入、中间量和输出 | 沿时间轴逐步执行 `U` 与 `T`，比较交换次序后的两个终点 | 上下两条同步流程轨道，各自只显示当前一步和终点 |
| §3 | 图中大面积空白，基向量像与矩阵列都太小 | 直接拖动两根列向量，让整张输出网格和矩阵两列同步改变 | 大网格为主，矩阵紧贴右侧；列向量拥有可见手柄 |
| §4 | 偏转网格太淡，文字读数抢占主画面，命中特征方向时反馈弱 | 旋转 `v`，观察 `Av` 与 `v` 之间的夹角连续缩到零 | 单一大圆盘，弧线显示偏转角，命中时整条特征直线强化 |
| §5 | 阶段按钮与三个滑杆竞争，真实向量过小，分解过程不直观 | 拖动一个过程滑杆，观察同一个 `x` 在两个同步坐标视图中的分解与独立缩放 | 标准坐标与特征坐标双视图，阶段只保留“读坐标、缩放、合成” |
| §6 | 把经过原点的 `ker T` 错画成仿射纤维 `x+ker T` | 拖动纤维基点，看整条正确的仿射纤维及其样本映到同一输出 | 输入与输出双平面，纤维严格经过当前 `x`，共同像固定在输出端 |
| §7 | 样本、像、泄漏线和矩阵挤在一起，无法看见整个子空间的像 | 旋转候选 `W`，直接比较整条 `W` 与整条 `T(W)` 是否重合 | 同一平面叠加两条完整子空间，角差为主，矩阵零块只作小型旁证 |
| §8 | 对角化失败、完整 `T`、幂零部分 `N` 和链同时竞争 | 依次剥离 `λI`，再让当前链向量沿 `N` 前进一步 | 三段式故事视图，每一段只保留当前所需的方形或链 |
| §9 | 只显示最终残量箭头和状态列表，没有显示多项式怎样作用 | 按次数逐项累加 `c_kT^kv`，观察向量和是否闭合到零 | 每个基方向一条向量累加轨道，同一进度控制逐项加入 |

## 十、本轮实现约束

- 九节不再共享“工具栏、统一舞台、滑杆区、结果大卡”的视觉模板；共享代码只保留数学计算、箭头和坐标换算。
- 所有可拖对象必须有显式圆环手柄与短操作提示；圆环表示控制点，不附着在普通向量箭头上。
- 颜色严格使用现有主题变量。青绿表示当前主对象，珊瑚表示对照或偏离，金色表示输入或待检验对象；灰色只作网格和历史状态。
- 图内文字只标记对象名称、角度或当前步骤；解释性段落移到图外。
- 桌面视图优先保证数学图形尺寸；手机端重排为单列，不把桌面 SVG 简单缩小到难以阅读。
- §6 的仿射纤维、§7 的整个像子空间和 §9 的全空间零化关系必须加入自动数学断言，不能只靠截图判断。
- 每三节完成一次真实浏览器验收；九节全部完成后再进行亮色、暗色、手机端、连续拖动、例题和公开预览复核。
