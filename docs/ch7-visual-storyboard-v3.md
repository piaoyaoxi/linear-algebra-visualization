# 第七章第三轮可视化分镜

> 内部制作资料，不进入学生页面。

## 1. 本轮截图暴露出的结构性失败

本轮用户截图中的 §6、§7、§8 说明，上一轮虽然移除了明显的向量端点错误，也修复了滑杆连续拖动，但页面仍没有达到“数学图像本身讲清概念”的标准。问题集中在以下几处：

1. **统一模板压过概念差异。** 三节都被组织成“预设按钮—左侧小坐标图—右侧说明栏—底部滑杆”，学生看到的是同一个后台面板换了数据。
2. **几何对象被切碎。** 核、值域、不变子空间和 Jordan 链本来都涉及整体结构，但旧图把它们拆成零散点、细箭头和指标表，学生无法形成连续空间图像。
3. **说明栏承担了本该由图像承担的工作。** 右侧标题和公式先给出结论，左侧图只是事后配图；学生不能通过操作自己发现结论。
4. **主要动作藏在底部控件。** 学生必须先找到滑杆，再猜数值变化与图像的关系。能够直接拖动空间对象的概念，应优先让学生在画布内操作。
5. **SVG 过度符号化。** 多个样本点、短箭头、十字和标签同时出现，虽然每个符号都“有意义”，合起来却没有清楚的视觉主线。

因此，本轮不再继续修饰 `cinematic.js` 的统一 `sceneLayout()`。新的 story 层在其后加载并重新注册九节 renderer，保留旧层作为回退，但学生实际看到的是九种独立场景。

## 2. 全章镜头语言

- 先出现一个可辨认的几何对象：网格、平行四边形、基向量、方向线、子空间带或向量轨道。
- 主要交互直接发生在画布中；底部 range 只作为精确输入和键盘无障碍补充。
- 一次只强调一个变化，其他对象降低透明度。
- 颜色在全章保持稳定：第一输入/第一基方向使用青绿，第二输入/第二基方向使用珊瑚，输出或当前结论使用紫色，失败泄漏使用红色，结构保持使用绿色。
- 向量使用单一闭合 path 绘制，箭杆与箭头是一体，不在箭头终点附加圆点。
- 圆点只表示可拖动样本或空间中的点；子空间用整条带或整块区域；像空间用完整集合形状。
- 公式出现在动画结论带中，并与当前视觉状态同步，不作为独立的大型说明卡。

## 3. 九节分镜

### §1 线性变换的定义：两条路径是否闭合

主画面是一对并列平面。学生直接拖动 `u`、`v` 两个箭头端点：

- 左侧形成输入平行四边形；
- 右侧同时绘制 `T(u+v)` 与 `T(u)+T(v)` 两条路径；
- 线性预设中两个终点重合，平移和绝对值预设中出现清楚的缺口。

阶段按钮只切换“原点—加法—数乘”，不同时堆叠三种检验。

### §2 线性变换的运算：同一个图形穿过不同机器

使用一条横向变换流水线，输入对象是一只不对称的小箭头旗形，避免旋转后仍看不出区别：

- `T+S` 显示同一输入分别经过 T、S 后在输出端进行向量相加；
- `T∘S` 与 `S∘T` 显示真实先后顺序；
- 逆变换显示能否沿原路径返回。

每一步只保留当前形状和一条淡色残影，不再使用三个小坐标框与指标表。

### §3 线性变换的矩阵：两根基向量拖动整张网格

主画面以标准网格和单位方格开始：

- 第一步只移动 `e₁`，第一列在箭头旁生成；
- 第二步只移动 `e₂`，第二列生成，整个网格随两列确定；
- 第三步出现可拖动点 `x=αe₁+βe₂`，其像始终由两列的同一系数组合得到；
- 最后切换基，只改变坐标网格和列记录，不移动真实 `x` 与 `T(x)`。

### §4 特征值与特征向量：在变形网格中寻找不转向的直线

一张全宽坐标平面同时显示原网格与变换后网格。学生直接抓住候选方向旋转：

- `v` 使用青绿箭头；
- `Av` 使用紫色箭头；
- 候选整条直线贯穿原点；
- 接近特征方向时两支箭头共线并出现吸附和伸缩比；
- 90° 旋转预设中任何方向都无法共线。

### §5 对角化：把混合运动拆成两个独立方向

采用三镜头故事板而非右侧说明卡：

1. 原坐标中，网格被混合拉伸；
2. 特征坐标中，向量分解成两个分量；
3. 两个分量独立缩放后重新合成 `Ax`。

同一个向量的颜色和位置关系跨三镜头连续。Jordan 预设直接停在“第二条独立特征方向缺失”，不伪造后续步骤。

### §6 核与值域：整张平面怎样压成线或点

这是本轮重点重做：

- 单一大画布显示原始网格逐渐变成 `T` 后的网格；
- “变换进度”从 0 到 1 连续插值，秩一时整张平面真实坍缩成一条线，零变换时坍缩到原点；
- 可拖动输入点 `x` 在同一画布中移动；
- 当学生沿核方向拖动时，最终输出标记保持不动，并留下同色轨迹；
- 值域直接由最终网格的形状呈现，不再用右侧数值表告诉学生。

### §7 不变子空间：比较整个 W 与 T(W)

不再绘制多个样本短箭头。画布中同时显示：

- 候选子空间 `W`：宽的半透明带；
- 变换后的整个集合 `T(W)`：另一条半透明带；
- 二者重合时整条带变绿；
- 不重合时，超出 `W` 的区域用红色显示。

学生直接拖动 `W` 的方向。一个探针向量仅作为辅助，明确区分“某个向量碰巧留下”与“整个子空间被保持”。

### §8 Jordan 标准形：同一特征线旁的剪切尾巴

先做对比，不先出现链条卡片：

- 左侧是可对角化情形，两条特征线独立伸缩；
- 右侧是 Jordan 块，只剩一条真正特征线，第二个方向在伸缩后被额外推向特征线；
- 切换到 `N=T−λI` 后，纯缩放被剥离，只剩“向前一级”的剪切位移；
- 点击“下一步”时，广义向量的像依次落入前一级，路径在同一画布中连续留下。

链关系作为画布底部的简洁标注，不再占据独立卡片。

### §9 最小多项式：用同一个多项式消掉整个空间

主画面分为两条基方向轨道，每条轨道在同一坐标平面中依次显示：

- `v`、`Tv`、`T²v` 等项；
- 当前候选多项式的加权向量和；
- 最终剩余箭头是否为零。

只有两条基方向都归零时，画面中央的“零算子”闭合。随后再比较是否能降低次数。这样学生直接看到局部消去与全局消去的差别。

## 4. 工程结构

新的实现拆成共享核心和九个小节文件：

```text
current/visuals/ch7/story.css
current/visuals/ch7/story-core.js
current/visuals/ch7/story-section1.js
...
current/visuals/ch7/story-section9.js
```

这些脚本在 `cinematic.js` 和 `drag-controls.js` 之后加载，通过现有 registry 覆盖同名 renderer。每个小节只维护自己的状态和事件，避免一个近千行文件再次形成万能面板。

## 5. 浏览器验收

每轮修改后都需要真实浏览器检查：

- 九节桌面亮色完整页面；
- 九节暗色主实验；
- 九节 390px 手机端；
- 画布直接拖动、range 拖动、触摸拖动；
- 逐节检查公式与图像同步；
- 无箭头端点圆球、标签遮挡、SVG 裁切、横向溢出；
- 第四章第一节和第四章其他成熟 renderer 回归正常。

CI 通过只是最低条件；最终必须逐张查看截图，发现视觉问题继续修改。
