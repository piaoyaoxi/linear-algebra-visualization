# 第四章《矩阵》教学蓝图

> 状态：课程设计稿。它确定第四章后续制作的边界、顺序与呈现取舍；不是教材逐页复述，也不是立即扩写页面的任务单。

## 0. 这章怎么用教材

教材只负责两件事：

1. 目录顺序与课程范围：本章严格沿用 §1—§7。
2. 学生在老师课堂、PPT 与讲义之间定位内容时，网站能够找到对应位置。

具体讲法不照搬教材。每节的内容按“学生真正需要理解的数学结构”组织；网站不承担电子教材的职责。

## 1. 全章制作原则

### 1.1 视觉只服务理解

- 只有空间变化、操作顺序、结构配对或逐步消元真正有助理解时，才使用交互或动画。
- 视频不是栏目配额；没有真实教学必要或没有真实视频源，就不显示视频区域。
- 静态图、推导、例题和短文字常常比动画更合适。

### 1.2 每节都要有“主问题”，但不要求同一套组件

一节的最小骨架是：

1. 这一节究竟要回答什么问题；
2. 必须出现的定义、规则或结论；
3. 一个能把概念压到计算或判断上的代表例题；
4. 小结与少量自测。

可选组件包括：概念短讲、交互实验、静态结构图、步进推导。它们按需要使用，不强行齐全。

### 1.3 先建立主线，再补充分支

第四章的主线是：

```text
矩阵是什么
→ 矩阵怎样运算
→ 乘积怎样改变缩放与有效维度
→ 何时可以恢复输入
→ 怎样用分块与初等操作组织计算
```

任何新增内容都必须服务这条主线；不把后续章节的线性空间、线性变换、标准形理论提前塞进来。

## 2. §1—§7 的最终内容边界

### §1 矩阵概念的一些背景

**核心问题**

矩阵为什么不是一张孤立的数字表格？它在方程组、线性关系和坐标记录中分别承担什么作用？

**必须讲清**

- 矩阵的行、列、阶、元素与相等；
- 矩阵如何把一组相关数字组织成可操作的对象；
- 用方程组或坐标关系说明矩阵出现的自然背景；
- 列向量视角作为直觉入口：矩阵的列可以记录基方向的去向；
- 为什么“先看列”有助于理解矩阵，而不是把矩阵只当成计算表格。

**明确不展开**

- 线性映射的严格公理化定义；
- 矩阵乘法、行列式、秩、可逆；
- 高维空间的抽象理论。

**最合适的呈现**

- 正文与一张干净的“行、列、阶”静态图；
- 现有网格变换交互保留，但只用于说明“列记录方向去向”，不让它吞掉本节的基础概念；
- 一道从两列读出二维变换的例题；
- 不需要视频。

**现有资产判断**

- `transform` 交互可复用；
- 现有“矩阵作为线性映射的记录”内容应当压缩为本节的后半段，而不是替代矩阵概念本身。

**开发优先级**：A。它是用户进入第四章时的基础入口，但不是完整黄金样板。

---

### §2 矩阵的运算

**核心问题**

为什么矩阵可以相加、数乘与相乘？尤其是，矩阵乘法为什么是复合，而不是普通的逐项运算？

**必须讲清**

- 同型矩阵加法与数乘；
- 转置的基本意义与最必要的运算规则；
- 矩阵乘法的尺寸条件；
- 行乘列公式的来源；
- 乘法的结合律、单位矩阵与一般不交换；
- 乘法的三层理解：变换复合、列向量、行列配对。

**明确不展开**

- 行列式与秩在乘积中的性质；
- 逆矩阵与可逆判定；
- 为了完整性而逐条证明所有运算律。

**最合适的呈现**

- 文字解释 + 现有“复合 / 看列 / 行列公式”三视角交互；
- 一个对比 `AB` 与 `BA` 的步进例题；
- 3—4 道带反馈的小自测；
- 视频可做，但只在真实短讲完成后出现；现阶段不能用只有脚本、没有视频源的数据假装视频模块存在。

**现有资产判断**

- `multiply` 交互是当前最值得保留和继续打磨的模块；
- 当前乘法内容需要从“一个漂亮的演示”提升为完整的定义、尺寸判断、行列公式和例题闭环。

**开发优先级**：A。

**完整黄金样板候选**：是。它天然需要概念问题、动态直觉、交互、多种表述、严格定义、步进例题、自测与小结，而不是为了凑组件硬塞内容。

### §3 矩阵乘积的行列式与秩

**核心问题**

矩阵连续作用后，面积或体积的缩放与“保留下来的独立方向”会怎样变化？

**必须讲清**

- `det(AB)=det(A)det(B)` 的含义：连续变换的缩放因子相乘；
- 秩作为有效维度，而不是单纯的计算结果；
- 秩与列向量独立方向的关系；
- `rank(AB) <= min(rank(A), rank(B))` 的结构性直觉；
- 行列式非零、满秩与不坍缩之间的最基础联系。

**明确不展开**

- 所有秩定理的完整证明；
- 行秩等于列秩的完整理论证明；
- 小子式定义与复杂计算技巧的堆砌。

**最合适的呈现**

- “平面保留 / 坍缩成线”的秩交互；
- 一张把乘积看作连续变换的静态结构图；
- 从列关系直接判断秩的例题；
- 不需要视频。

**现有资产判断**

- `rank` 交互可复用，但当前展示只是概念演示，后续要补齐与乘积、行列式的连接；
- 当前内容只覆盖了秩的一部分，尚不够承担教材 §3 的完整主题。

**开发优先级**：B。

---

### §4 矩阵的逆

**核心问题**

什么样的矩阵能把输出唯一地还原成输入？这种“信息不丢失”怎样同时出现在公式、几何和方程组里？

**必须讲清**

- 逆矩阵的定义与单位矩阵；
- 方阵才可能有逆；
- 可逆与行列式非零、满秩、唯一解之间的核心等价关系；
- 2 阶矩阵求逆公式与它的限制；
- 用 `AX=I` 的观点理解求逆。

**明确不展开**

- 把全部可逆等价条件证明一次性塞入本节；
- 一般 n 阶矩阵的伴随矩阵公式推导；
- 依赖初等变换的通用求逆算法细节：这部分应在 §6 回收。

**最合适的呈现**

- 静态“可逆 / 坍缩”对照；
- 2 阶矩阵求逆的步进例题；
- 一组概念判断题；
- 不需要视频，交互也不是第一优先级。

**现有资产判断**

- 现有内容有正确的几何直觉和例题雏形；
- `slot` 只是占位，不能被算作已经完成的交互。

**开发优先级**：B。

---

### §5 矩阵的分块

**核心问题**

为什么把大矩阵按有意义的行列切开后，结构和计算都会更清楚？

**必须讲清**

- 分块不是任意画格子：行列切法必须匹配；
- 分块加法、数乘与乘法的尺寸条件；
- 块乘法的“行乘列”本质没有改变；
- 块对角矩阵对应相互独立的子系统；
- 分块帮助看见结构，而不是单纯减少书写。

**明确不展开**

- 通用分块求逆公式；
- Schur 补作为主线内容；
- 与后续标准形、直和分解的深层理论联系。

**最合适的呈现**

- 静态分块结构图；
- 块尺寸配对的高亮图；
- 块对角矩阵的代表例题；
- 不需要视频；交互只有在“高亮配对过程”足够清楚时才值得做。

**现有资产判断**

- `block` 的视觉渲染函数已经存在，但目前不会被 `getInteractive` 识别并输出；因此它是“可用代码片段”，不是已经完成的教学模块。

**开发优先级**：C。

---

### §6 初等矩阵

**核心问题**

为什么一次初等行或列变换等于乘一个特定矩阵？左乘和右乘为什么分别影响行与列？

**必须讲清**

- 三类初等行变换与对应初等矩阵；
- 对单位矩阵做同样操作即可构造初等矩阵；
- 左乘对应行变换，右乘对应列变换；
- 初等矩阵可逆，逆矩阵对应反向操作；
- 多步消元如何写成初等矩阵的乘积。

**明确不展开**

- 再次从头讲完整消元算法；
- 把等价标准形、秩、求逆的所有应用都堆在一节；
- 分块初等变换：留给 §7。

**最合适的呈现**

- 逐步高亮的消元演示值得做；
- 一道“从行操作构造 E，并验证 EA”的步进例题；
- 不需要独立短视频。

**现有资产判断**

- 当前只有 `slot` 占位与文字提示，没有真实的逐步演示。

**开发优先级**：B，在 §4 之后制作最顺。

---

### §7 分块乘法的初等变换及应用举例

**核心问题**

怎样把分块和初等变换组合起来，让复杂矩阵的计算变成结构化的消元过程？

**必须讲清**

- 块初等操作的尺寸与方向条件；
- 分块消元的基本写法；
- 两类应用：
  1. 块三角系统的求解；
  2. 通过分块初等变换处理一个结构化的逆或等价问题；
- 每一步为什么合法，而不只是背操作模板。

**明确不展开**

- 把 Schur 补做成先修要求；
- 所有高级分块公式与泛化结论；
- 为了“应用”而虚构无关场景。

**最合适的呈现**

- 步进推导优先；
- 需要时用块高亮帮助阅读；
- 不需要视频；不把动画当作这节的卖点。

**现有资产判断**

- 当前仅有准确的目录位置与占位说明；后续应当在 §5 和 §6 的基础组件成熟后再制作。

**开发优先级**：C，最后制作。

## 5. 每节完成的最低标准

一个小节只有同时满足下列条件，才算完成：

- 用户能在首页、目录与页内标题中明确知道它对应哪一节；
- 页面有一个清楚的主问题，不是概念清单；
- 定义和结论没有被视觉效果替代；
- 至少有一个真正服务核心概念的例题；
- 视觉、交互、视频都经过“是否必要”的判断；
- 自测或思考题能检验本节最容易混淆的点；
- 例题、交互和小结的叙述彼此一致。

- 发布 GitHub Pages；

- 合并本分支；
