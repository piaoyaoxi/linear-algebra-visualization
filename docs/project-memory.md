## 1. 项目定位

项目名称可以朴素地叫“高等代数可视化”或相近名称。核心定位是北大版《高等代数》的教材伴学网站。

网站的价值不在于替代教材，也不在于做题库或 AI 解题器。它要补足纸面教材和课堂板书很难表达的部分：空间如何变化、过程如何展开、抽象对象如何被看见、学生如何通过拖动参数得到即时反馈。

当前样板章是第四章“矩阵”。原因是矩阵连接了表格记号、运算、线性映射、复合、行列式、秩、可逆、初等变换和分块结构，适合先把网站形态打通。

## 2. 学生页面的硬规则

- 学生页面不显示“开发进度”“原型版本”“占位”“即将制作”“待补充”等项目内部语言。
- 学生页面没有真实视频源时，不显示视频区域。
- 学生页面没有真实交互内容时，不显示空交互区域。
- 避免在学生页面使用“不是……而是……”这类容易让学生误记的句式。用正向、直接的表达。
- 例题答案默认折叠或渐进展开，让学生先思考。
- 视觉效果只服务理解。玻璃质感、动效、首页氛围不能压过数学内容。
- 正文、公式、例题区要保持清晰实底；玻璃质感主要用于导航、侧栏、顶部控件和少量信息层。

## 3. 小节页面结构

推荐小节结构：

```text
起点问题
概念短讲视频：有真实视频源才显示
交互实验：有真实交互才显示
定理概念：KaTeX、教材对应位置、必要定义
代表例题：折叠或步进展开
自测：少量题，即时或折叠反馈
小结：一句主线、前后连接、常见误区、标记掌握
```

短片与交互的关系：

- 需要完整叙事的概念做短片，长度大约 1-3 分钟，可用 Manim，后续可接本地 TTS。
- 短片下面可以放交互实验，帮助学生把刚看到的动画改成自己可操作的实验。
- 只需要观察参数变化的小节，直接做交互实验。
- 偏符号规则、推导、教材地图性质的小节，保留导读、例题和自测即可。

## 4. 当前代码事实

当前主应用在 `current/`。

短片是可选的。`current/app.js` 里的 `getVideo(section)` 只在 `section.video.src` 或 `section.video.embed` 存在时返回视频。真实可播放内容继续放在 `video` 字段；未来短片脚本、镜头草案等内部计划放在 `videoPlan` 字段或文档里，不进入前台视频模块。

交互也是可选的。`getInteractive(section)` 先检查小节是否显式声明 `interactive`：有则按该字段渲染，`interactive: false` 可明确关闭；没有时再兼容读取 `visual`。自动识别的真实交互类型包括 `transform`、`multiply`、`rank`、`block`。`slot` 不自动出现，只用于显式 `interactive` 或后续增强脚本需要稳定容器的情况。

当前渲染顺序在 `renderLessonPage()` 中已经符合项目方向：

```text
概念问题 -> 视频 -> 交互 -> 定理概念 -> 代表例题 -> 自测 -> 小结
```

现有第四章关键资源：

- `transform`：矩阵改变网格，归入 §1。
- `multiply`：矩阵乘法三视角，归入 §2，是黄金样板核心交互。
- `rank`：秩与独立方向，归入 §3。
- `block`：已可通过 `interactive` 或 `visual.type = "block"` 渲染，归入 §5。
- `slot`：只作为显式增强容器，不自动视为真实交互动画。

PDF 元信息：

目录中适合我们借鉴的主题：

- 向量：向量加减法、数乘、内积、投影、范数。
- 矩阵：矩阵乘法、矩阵乘法的几何视角、矩阵乘法多个视角。
- 行列式：2x2、3x3、性质、手算。
- 逆矩阵：逆矩阵、性质、求逆。
- 向量空间、线性方程组、几何变换、投影、Gram-Schmidt、QR。
- 特征值分解、二次型、SVD 等后续可视化价值很高。

已经重点看过的小节：`2.5 矩阵乘法的几何视角`，PDF 物理页大约 190-202。

这一节的主线非常适合改编成动画：

```text
Ax = y
-> A 把输入向量从 p 维空间送到 m 维空间
-> 2x2 矩阵拖动平面网格
-> e1、e2 的去向决定矩阵两列
-> 旋转、缩放、镜像、剪切等例子
-> 3x3 空间变换
-> 3x2 把二维嵌入三维
-> 2x3 把三维投影到二维
-> 逆变换作为“把变化撤回去”
```

可借鉴点：

- 先从 `Ax=y` 的形状和输入输出讲起，再进入几何图像。
- 2x2 部分最适合做短片：两个基向量拖动整张网格。
- 3x2 / 2x3 很适合将来做“升维嵌入”和“降维投影”的交互。
- 这本书的图像思路很强，但网站应重画自己的动画和图，不直接复制图片或长段文字。

重要代码观察：

- 3B1B 这套代码使用旧版 ManimGL / `manimlib` 风格。我们后续实现应优先用 ManimCE，并把思路翻译过去。
- `chapter3.py` 是线性变换核心：一个向量、很多向量、整张网格、基向量、矩阵列。
- 常见基类/方法：`LinearTransformationScene`、`VectorScene`、`apply_transposed_matrix(...)`。
- 叙事顺序值得借鉴：先动一个向量，再动很多向量，再动整张网格；最后记录 `i_hat`、`j_hat` 的落点，把它们拼成矩阵列。
- `chapter4.py` 是复合与矩阵乘法：先做旋转，再做剪切，最后把两次变换合成为一个乘积矩阵。
- `chapter10.py` 是特征值特征向量：`TweakLambda` 一类场景展示 `(A - lambda I)`、行列式变化、网格坍缩和特征方向。

最值得借鉴的是它的镜头语言：

```text
提出问题
-> 先给一个可见对象
-> 让对象连续变形
-> 保持颜色和对象连续性
-> 把图像落回公式
-> 用同一视觉语言解释下一层抽象
```

## 9. 动画与交互的工程路线

短片路线：

```text
资料拆解
-> scenes.md 镜头脚本
-> ManimCE 代码
-> 渲染 mp4/webm
-> 可选 TTS 音频
-> 放入 current/assets/videos/
-> 在内容数据里填写 video.src 或 video.embed
```

交互路线：

```text
确定学生要通过操作回答的问题
-> 设计可调参数
-> 用 Canvas / SVG / HTML 控件实现
-> 放到 renderVisualPanel 或专门 presentation 脚本
-> 小节数据通过 visual / interactive 指定
```

重要原则：

- 短片负责讲清一条线性叙事。
- 交互负责让学生亲手改变参数，验证边界情况。
- 二者可以共用同一套数学对象和视觉语言。
- 没有操作问题的“交互”不要做；没有叙事必要的“短片”不要做。
